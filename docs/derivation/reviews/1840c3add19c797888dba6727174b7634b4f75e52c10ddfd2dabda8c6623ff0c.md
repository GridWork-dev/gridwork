The five `.rs` files land the reverse PTY input path: the kernel forwards a consumer's

- `kernel_client.rs` — the read half moves off a shared `&mut self.stream` borrow onto a
  dedicated background task (`read_controls`) feeding a bounded `mpsc` channel, so a reverse
  control and an in-flight request/response can share one connection without blocking each
  other; `consume_input` decodes the base64 payload, checks it against the declared byte
  count and two size ceilings, and forwards the raw bytes to a new `Attacher` handle, or
  passes any non-input control through unchanged.
- `publish.rs` — the per-session forwarding loop's `tokio::select!` gains a
  `client.wait_for_control()` / `apply_input_control()` arm alongside the existing delta,
  raw-event and stop arms.
- `registry.rs` — `Attacher` gains `id()` and an `input()` method (a timeout-bounded
  round trip over the session's existing command channel); `SessionRegistry::input` now
  delegates to it instead of sending the command inline.
- `session.rs` — `SessionCommand::Input` gained a `reply: oneshot::Sender<Result<(), String>>`
  field so a write failure reaches the caller as a value, not only a log line.
- `wire.rs` — `WireScreen` gained a `cursor: Option<PtyCursor>` field, set from the engine
  frame's `(col, row)` tuple and carried into `PtyFrame::snapshot()`; one existing byte-count
  test was re-pinned for the larger serialized frame.
