**Index alignment: holds for wide cells and spacers, breaks for a ZWJ sequence the
engine splits across cells.** The claim under review is `Row::styles`' "one entry per
grapheme pushed into `text` ... so the two stay index-aligned" and the render-loop
comment "styles[i] describing `text`'s i-th grapheme". Probes:

- A wide emoji between two styled narrow cells: text and styles stay aligned, the
  spacer contributes neither a grapheme nor a style entry, the blank tail is unstyled,
  and `styles.len()` equals the pushed-grapheme count, not the column count. The
  documented rule holds. PASS.
- A woman+ZWJ+laptop emoji sequence between two styled narrow cells, default modes:
  the engine stores it as TWO cells (the joiner-terminated half, then the second
  emoji), so `text` receives two pushes that UAX-29 segmentation of the concatenated
  string merges into ONE grapheme — `styles` carries an entry per push (8) while
  `text` has fewer UAX-29 graphemes, and a consumer segmenting `text` per UAX-29 (the
  reading the crate's own UAX-29 row licenses) reads the wrong style for every
  grapheme after the split cluster: the cell after the sequence reads the sequence's
  color instead of its own. Verified precisely: with per-cell colors red/green/yellow,
  the UAX-29-indexed style for the trailing cell is green, not yellow. FAIL against
  the sentence as written.
- Same sequence with grapheme clustering enabled (`CSI ? 2027 h`): one cell, one
  push, one style entry — alignment holds perfectly.

So the alignment claim is conditionally true — per pushed cluster always, per UAX-29
grapheme of `text` only when the child has grapheme clustering active — and the doc
states it unconditionally. This is a documentation-contract defect and a missing test
pin, not a clean-room violation: nothing about it is derived from an unpermitted
source, and the UAX-11 marker beside the loop is scrupulous about what it does and
does not claim. Recorded as a required finding: weaken the `Row::styles` sentence and
the render-loop comment to per-pushed-cluster alignment (or document the
grapheme-clustering condition), and pin the split-cluster case in the fidelity suite.
