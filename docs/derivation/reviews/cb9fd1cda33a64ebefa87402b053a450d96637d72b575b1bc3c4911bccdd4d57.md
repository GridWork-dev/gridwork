## Scope

One gated path: `crates/gridwork/src/tui.rs`. The change fixes a clock-skew bug in
"today's spend" (`refresh_hall_cost`): the day boundary used to come from this
process's own clock (`current_timestamp()`) while every row it is compared against is
stamped by the kernel's database clock, so a client a few minutes off across midnight
could report a different total over identical rows. The fix widens the wire read
(`read_projection_records` / `ProjectionRead`, replacing a bare 3-tuple with a named
struct) to carry the kernel's own `served_at` timestamp, uses it as the day boundary
when present, and threads a new `hall_cost_kernel_clocked: bool` through
`ConsoleModel` and into the draw call so a surface can say whose midnight it means
when it falls back to the local clock (a kernel predating the field). The rest of the
diff is mechanical: three other tuple-destructuring call sites
(`refresh_queue`, `refresh_terms`, `refresh_config`, `read_projection_records_once`,
`load_projection_pages`) adapt to the struct shape, discarding the new `served_at`
field with `_` where it isn't needed.
