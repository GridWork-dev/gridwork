### Fail-closed relay (design property, re-affirmed — file unchanged)

`relay_ask` cannot fail open: infallible by signature; the only non-`Deny` value is a
`HookDecision` serde-parsed (with `deny_unknown_fields`) from the server's reply. Every
failure — no listener, elapsed deadline, socket timeout, oversized reply, malformed or
unknown-field reply, peer hang-up — collapses to `Deny` with a reason. Seeded negatives
present: `a_client_that_gets_no_response_before_the_deadline_fails_closed_to_deny` and
`a_client_with_nobody_listening_fails_closed_to_deny`. Server side drops unauthorized or
malformed peers unanswered, landing the client on its deadline → `Deny`. Liveness nit,
non-blocking: the client's read timeout is armed once from the remaining budget and applies
per syscall, so a drip-feeding peer can stretch wall time past `deadline`; the outcome is
still only delay then `Deny` or the server's own answer — never fail-open.
