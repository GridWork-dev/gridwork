### Every round-1 finding is fixed, and each fix's citation now holds

1. `cost.rs` `TokenUsage`/`TokenCacheUsage`: spec `Session.tokens` =
   `{ input, output, reasoning, cache }` all four required, `cache` =
   `{ read, write }` both required — exactly what the structs model. The old flat
   `cacheRead`/`cacheWrite` shape is kept as a failing regression case.
2. `event.rs` `reply_action`: `POST /permission/{requestID}/reply` (operation
   `permission.reply`, body key `reply`, no `deprecated` flag) is real; the sibling
   `POST /session/{sessionID}/permissions/{permissionID}` (operation
   `permission.respond`, body key `response`) carries `deprecated: true` in the spec,
   exactly as the marker says; the `/api/...` route is operation
   `v2.session.permission.reply`, and the v2 events are separately named
   `permission.v2.asked`/`permission.v2.replied` — the marker's v1/v2 channel-pairing
   rationale is substantiated.
3. `event.rs` `ToolRef`: spec schema is literally named `PermissionRequest`; its `tool`
   is `{ messageID, callID }` both required whenever present, and `tool` is absent from
   `PermissionRequest.required` — matching `Option<ToolRef>`. A regression test asserts
   the old string-`tool` shape now fails to parse.
4. `event.rs` `SessionStatus`: spec is a `type`-tagged union — `{type:"idle"}`,
   `{type:"busy"}`, `{type:"retry"}` with `attempt`/`message`/`next` all in `required`
   and an optional `action` the marker discloses as not modeled. The
   `#[serde(tag = "type")]` enum matches variant-for-variant, field-for-field.
5. `event.rs` `normalize`: `session.created`/`session.deleted` properties are
   `{ sessionID, info: Session }` — `parentID` is read from `info.parentID` (spec:
   `Session.parentID`, pattern `^ses`, optional), no longer from a nonexistent
   top-level field; `permission.replied` properties are `{ sessionID, requestID,
   reply }` — the code reads `requestID` and parses `reply` through the same
   three-value decision enum (`once`/`always`/`reject`, verified on all three reply
   bodies); `session.error` now carries the typed union — all eight variant names in
   the marker (`ProviderAuthError`, `UnknownError`, `MessageOutputLengthError`,
   `MessageAbortedError`, `StructuredOutputError`, `ContextOverflowError`,
   `ContentFilterError`, `APIError`) match the spec's anyOf exactly, every variant is
   `{ name, data }` both required, and `data.message` is required on seven and absent
   only on `MessageOutputLengthError` (whose `data` has no properties) — the marker's
   precise claim, true to the letter.

### One minor, non-blocking imprecision (recorded, not escalated)

The `normalize` marker's shorthand `session.error` carries `{ sessionID, error? }`
marks only `error` optional, but `EventSessionError`'s inner properties carry no
`required` list at all — per the published schema `sessionID` is optional there too
(unlike `session.idle`, which does require it). The field names, types, and the error
union are all substantiated; the only consequence is that a hypothetical
`session.error` frame without a `sessionID` becomes a typed `Malformed` parse error
rather than a normalized event — an unattributable error the adapter could not have
turned into a session fact anyway. Worth one `?` in the marker on a future touch; not a
behavior without a citable source.
